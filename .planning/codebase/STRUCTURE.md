## Directory Purposes

**src/components/**
- Purpose: All React UI components organized by feature/responsibility
- Contains: Presentation components, container components, modals, pages
- Key files: `EditorContainer.jsx` (orchestrator), `SheetView.jsx` (main display), `ChatSidebar.jsx` (chat)
- Breakdown: 23 .jsx files total; subdirectories group related components (auth, sheet, common, home)

**src/contexts/**
- Purpose: React Context providers for global state
- Contains: AuthContext (user + login/logout), SourceSheetContext (sheet data)
- Note: SourceSheetContext may be deprecated in favor of useSheetPersistence hook
- Used by: Wrapped around App in main.jsx

**src/hooks/**
- Purpose: Custom React hooks encapsulating reusable logic
- Contains: State management, persistence, sidebar UI, chat, database operations
- Key hook: `useSheetPersistence.js` - master hook for all sheet operations
- Pattern: All hooks prefixed with `use*`, exported as named exports

**src/services/**
- Purpose: Business logic and external API integrations
- Contains: Firebase Auth/Firestore, Sefaria text API, Gemini AI, Google Docs, DOCX export
- Pattern: Each service is a module with named export functions
- No state management - pure functions or class instances

**src/data/**
- Purpose: Static data, constants, configuration
- Contains: Prompt templates for AI in multiple languages
- Pattern: PROMPTS_EN and PROMPTS_HE objects exported

**src/i18n/**
- Purpose: Internationalization helpers
- Contains: Text translation functions (likely utility functions for EN/HE)

**src/styles/**
- Purpose: Global CSS stylesheets
- Contains: Layout, themes, responsive design, dark mode support
- Applied via: CSS class selectors in components, inline styles in JSX

**src/test/**
- Purpose: Test files (co-located or separate)
- Contains: Unit tests (useUndoRedo.test.js), integration tests (SheetFlow.test.jsx, SefariaService.test.js)
- Setup: vitest.config.js + test/setup.js
- Pattern: `.test.js` and `.test.jsx` files alongside source

**api/**
- Purpose: Serverless backend functions (Vercel deployment)
- Contains: `chat.js` - POST /api/chat endpoint for Gemini AI
- Runtime: Node.js (server-side code, secrets safe)

**public/**
- Purpose: Static assets served without processing
- Contains: Favicon, PWA manifest, Service Worker
- Deployment: Served directly from CDN/edge

**.planning/codebase/**
- Purpose: GSD (Generative Software Development) planning documents
- Contains: ARCHITECTURE.md, STRUCTURE.md (this file), CONVENTIONS.md, TESTING.md, STACK.md, INTEGRATIONS.md, CONCERNS.md

## Naming Conventions

**Files:**
- Components: PascalCase + `.jsx` (e.g., `EditorContainer.jsx`, `SourceBlock.jsx`)
- Hooks: camelCase with `use` prefix + `.js` (e.g., `useSheetPersistence.js`, `useUndoRedo.js`)
- Services: camelCase + `.js` (e.g., `firebase.js`, `sefaria.js`)
- Tests: `.test.js` or `.test.jsx` suffix (e.g., `useUndoRedo.test.js`)
- Data/Config: camelCase + `.js` (e.g., `prompts.js`)
- Styles: kebab-case + `.css` (e.g., `AppShell.css`, `LayoutFixes.css`)

**Directories:**
- Feature directories: PascalCase + plural or feature name (e.g., `components/`, `auth/`, `sheet/`)
- Utility directories: camelCase (e.g., `contexts/`, `hooks/`, `services/`)
- Asset directories: lowercase (e.g., `api/`, `public/`, `dist/`)

**React Components (within .jsx):**
- Component names: PascalCase (e.g., `function EditorContainer() { ... }`)
- Props: camelCase (e.g., `darkMode`, `toggleDarkMode`, `onAddSource`)
- State variables: camelCase with verb-noun pattern for booleans (e.g., `isLoading`, `isSaving`, `canUndo`)

**Functions/Exports:**
- Service functions: camelCase, descriptive verbs (e.g., `getSefariaText()`, `saveSheetToFirestore()`, `loginWithGoogle()`)
- Hook returns: Objects with state and handlers (e.g., `{ state, setState, undo, redo, canUndo, canRedo }`)
- Event handlers: `on*` prefix (e.g., `onAddSource`, `onRemoveSource`, `onReorder`)

**Constants:**
- Exported from modules: camelCase or UPPER_CASE depending on convention in file
- Example: `BASE_URL`, `MAX_REQUESTS_PER_WINDOW` (sefaria.js, chat.js)
- Example: `SYSTEM_INSTRUCTION` (api/chat.js)

## Where to Add New Code

**New Feature (e.g., new page or workflow):**
1. Create component in `src/components/` or subdirectory
2. Create hook(s) in `src/hooks/` if state management needed
3. Add service function in `src/services/` if external API integration needed
4. Add route in `src/App.jsx` Routes
5. Add tests in `src/test/` with descriptive name

**New Component/Module:**
- Presentation component: `src/components/FeatureName.jsx`
- Feature-specific sub-components: `src/components/feature/FeatureName.jsx` and `src/components/feature/SubComponent.jsx`
- Container/Smart component: `src/components/FeatureContainer.jsx`
- Shared component: `src/components/common/SharedComponent.jsx`
- Each component is a separate file (no barrel files by convention)

**Utilities:**
- Custom hook: `src/hooks/useFeatureName.js`
- Service/API client: `src/services/serviceName.js`
- Static data: `src/data/dataName.js`
- Internationalization strings: Add to `src/i18n/` or inline in `src/data/prompts.js`

**Styles:**
- New global styles: `src/styles/FeatureName.css` (import in `src/main.jsx` or component)
- Component-scoped styles: Inline styles in JSX or CSS-in-JS library (not currently used, but could be added)

**Tests:**
- Component test: `src/test/ComponentName.test.jsx`
- Hook test: `src/test/useHookName.test.js`
- Service test: `src/test/integration/ServiceName.test.js`
- Setup: All tests use `vitest` runner, can import from `vitest`, `@testing-library/react`, etc.

**Backend Functions:**
- New Vercel function: `api/newFunction.js` (export default handler)
- Shared API logic: Create utility file in `api/` directory or shared module

## Special Directories

**node_modules/**
- Purpose: npm package dependencies
- Generated: Yes (by `npm install`)
- Committed: No (in .gitignore)
- Size: ~500MB+ (typical)

**dist/**
- Purpose: Production build output from Vite
- Generated: Yes (by `npm run build`)
- Committed: No (in .gitignore)
- Contents: Minified JS, CSS, HTML, assets

**.planning/codebase/**
- Purpose: GSD (Generative Software Development) planning documents
- Generated: By `/gsd:map-codebase` orchestrator
- Committed: Yes (for future reference)
- Files: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, STACK.md, INTEGRATIONS.md, CONCERNS.md

**.git/**
- Purpose: Git version control repository
- Generated: Yes (by `git init`)
- Committed: No (hidden)

**.env files**
- Purpose: Environment configuration and secrets
- .env: Secrets and config (NOT committed, but exists in repo)
- .env.example: Template showing required variables (committed)
- .env.local: Local overrides (NOT committed, in .gitignore)
- Contents: API keys, Firebase config, Gemini API key, etc.

**public/**
- Purpose: Static assets served without transformation
- Generated: No (hand-created)
- Committed: Yes
- Examples: favicon.png, manifest.json, sw.js
